# Plan 04: Rate Limiting + Quota + Budget Control

**Objective:** 实现可配置的多模式限流系统，支持纯本地、纯 Redis、混合租约、区域分片四种架构，通过门面模式提供统一接口，兼容 Redis 集群模式，按配置选择具体实现。

**核心设计：门面模式 + 策略模式 + Redis 集群兼容**

```
┌─────────────────────────────────────────────────────────┐
│  调用方（中间件）                                         │
│  limiter.Check(ctx, keys, metric, cost)                │
└────────────────┬────────────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────────────────┐
│  RateLimiter (Facade 接口)                              │
│  - Check() / Release() / Correct()                     │
│  - GetAvailable() / Reset()                            │
└────────────────┬────────────────────────────────────────┘
                 │ 根据配置选择实现
                 ▼
    ┌────────────┴────────────┬────────────────┬──────────┐
    │                         │                │          │
    ▼                         ▼                ▼          ▼
┌─────────┐            ┌──────────┐     ┌─────────┐  ┌──────────┐
│  Local  │            │  Redis   │     │ Hybrid  │  │ Sharded  │
│  Mode   │            │  Mode    │     │  Mode   │  │  Mode    │
└─────────┘            └──────────┘     └─────────┘  └──────────┘
纯本地令牌桶          纯 Redis+Lua    本地粗筛+       区域分片
零网络延迟            强一致          中心精确        超大规模
适用单实例            适用中小集群     适用高并发      热点租户
                                     多租户场景      
```

## 一、四种限流架构模式

### 模式 1：纯本地（Local Mode）

**适用场景**：
- 开发环境、单 Pod
- 实例数 ≤ 1
- 对超卖不敏感的内部服务

**实现**：
- 本地令牌桶（`golang.org/x/time/rate` 或自研）
- 本地信号量（并发控制）
- 零网络延迟，亚毫秒级

**缺点**：
- N 实例会把全局配额放大 N 倍
- 例：配 100 TPM/实例、10 实例，实际可能放 1000 TPM

**配置示例**：
```yaml
ratelimit:
  mode: local
  local:
    rpm: 1000
    tpm_input: 50000
    tpm_output: 25000
    concurrency: 100
```

### 模式 2：纯 Redis（Redis Mode）

**适用场景**：
- 实例数少（≤ 3-5 个）
- RPS 不高（< 10k）
- 租户按 token 严格计费
- 需要强一致性

**实现**：
- 每次请求走 Redis + Lua 原子扣减
- 多实例共享一个真理源
- 令牌桶用 Lua 算 refill + consume
- 滑动窗口用 Sorted Set

**优点**：
- 多实例强一致，配额不超卖
- 审计方便

**缺点**：
- 每请求多 0.5-2ms（同机房）
- Redis 成瓶颈/单点
- 单 Redis 一般几万到十万级 ops

**配置示例**：
```yaml
ratelimit:
  mode: redis
  redis:
    url: redis://localhost:6379/0
    timeout: 100ms
  levels:
    global:
      rpm: 10000
      tpm_input: 2000000
      tpm_output: 1000000
    tenant:
      rpm: 500
      tpm_input: 100000
```

### 模式 3：混合租约（Hybrid Mode）

**适用场景**：
- 中高并发（10k-100k RPS）
- 多实例（> 5 个）
- 多租户，需要跨实例公平
- 允许短暂超卖（精度换性能）

**实现**：三层架构

```
L1 本地粗筛 → L2 中心 Redis 精确 → L3 本地兜底
```

**子模式**：

**A. 本地预检 + 超限才查 Redis**
- 本机计数器上限 = 全局配额/N × 安全系数
- 没超就直接放行，超了再查 Redis
- 热点租户大部分请求不碰 Redis

**B. 租约/批量领取（Token Lease）**
- 实例定期从 Redis 领"本机一段时间额度"（如每 1-5 秒领一批）
- 本地发完再领
- 流式结束把实际用量回写中心
- Redis 调用量从"每请求 1 次"降到"每批 1 次"
- 超卖量 ≈ 实例数 × 单批租约

**C. 本地桶 + 异步对账**
- 本地令牌桶按总配额/N 运行
- 后台每秒把本机消耗推给 Redis、拉全局剩余
- 动态缩扩本地桶容量
- 精度介于纯本地和纯 Redis 之间

**Redis 故障降级策略**：
- 计费/租户硬配额：fail-closed（429）或降级到本地快照配额
- 普通 RPM/突发：fail-open + 本地保守桶（总配额/N × 0.5-0.7）
- 并发信号量：纯本地控制，不依赖 Redis

**配置示例**：
```yaml
ratelimit:
  mode: hybrid
  hybrid:
    lease_mode: batch  # batch | precheck | async
    lease_interval: 1s
    lease_batch_size: 1000
    local_safety_factor: 0.8
    
    redis:
      url: redis://localhost:6379/0
      timeout: 100ms
      circuit_breaker:
        enabled: true
        error_threshold: 5
        timeout: 30s
    
    fallback:
      billing_quota: snapshot
      rpm_protection: conservative_local
      concurrency: local_only
```

### 模式 4：区域分片（Sharded Mode）⭐ 超大规模

**适用场景**：
- 超大规模（> 100k RPS）
- 多地域部署
- 超大客户需要物理隔离
- 热点租户导致单 Redis 节点瓶颈

**核心问题**：
- 超大租户（如月活百万的用户）的限流 key 集中在一个 Redis 节点
- 单节点 CPU/内存/网络成为瓶颈
- 需要把热点租户的限流数据分散到多个 Redis 节点

**实现方案**：

#### 4.1 Key 分片策略

```go
// internal/ratelimit/sharded.go

// ShardedRateLimiter implements rate limiting with key sharding for hot tenants.
type ShardedRateLimiter struct {
    clients       map[string]redis.UniversalClient  // shard_id -> Redis client
    shardStrategy *ShardStrategy
    configs       LevelConfigs
}

// ShardStrategy determines how to shard keys.
type ShardStrategy struct {
    // Hot tenants with custom shard count
    HotTenants map[string]int  // tenant_id -> shard_count
    
    // Default shard count for normal tenants
    DefaultShardCount int
    
    // Sharding method: "request_hash" | "round_robin" | "consistent_hash"
    Method string
}

// ShardKey creates a sharded key for a tenant.
// Example: tenant "abc123" with 16 shards
//   rl:tenant:{abc123}:shard:0:rpm
//   rl:tenant:{abc123}:shard:1:rpm
//   ...
//   rl:tenant:{abc123}:shard:15:rpm
func (s *ShardedRateLimiter) ShardKey(
    dim Dimension,
    tenantID string,
    metric Metric,
    requestID string,
) string {
    shardCount := s.getShardCount(tenantID)
    
    if shardCount <= 1 {
        // No sharding for small tenants
        return fmt.Sprintf("rl:%s:{%s}:%s", dim, tenantID, metric)
    }
    
    // Determine shard based on request
    shard := s.determineShard(tenantID, requestID, shardCount)
    return fmt.Sprintf("rl:%s:{%s}:shard:%d:%s", dim, tenantID, shard, metric)
}

func (s *ShardedRateLimiter) determineShard(
    tenantID string,
    requestID string,
    shardCount int,
) int {
    switch s.shardStrategy.Method {
    case "request_hash":
        // Hash request ID to determine shard
        h := fnv.New32a()
        h.Write([]byte(requestID))
        return int(h.Sum32() % uint32(shardCount))
        
    case "round_robin":
        // Round-robin across shards
        return int(atomic.AddUint64(&s.roundRobinCounter, 1) % uint64(shardCount))
        
    case "consistent_hash":
        // Consistent hashing for better distribution
        return consistentHash(requestID, shardCount)
        
    default:
        return 0
    }
}
```

#### 4.2 热点租户检测

```go
// HotTenantDetector detects hot tenants based on request rate.
type HotTenantDetector struct {
    mu            sync.RWMutex
    tenantStats   map[string]*TenantStats
    threshold     int64  // requests per minute to be considered "hot"
    checkInterval time.Duration
}

type TenantStats struct {
    TenantID      string
    RequestCount  int64
    LastReset     time.Time
    IsHot         bool
    ShardCount    int
}

// Start starts the hot tenant detection loop.
func (d *HotTenantDetector) Start(ctx context.Context) {
    ticker := time.NewTicker(d.checkInterval)
    defer ticker.Stop()
    
    for {
        select {
        case <-ctx.Done():
            return
        case <-ticker.C:
            d.checkHotTenants()
        }
    }
}

func (d *HotTenantDetector) checkHotTenants() {
    d.mu.Lock()
    defer d.mu.Unlock()
    
    now := time.Now()
    for tenantID, stats := range d.tenantStats {
        // Calculate RPM
        elapsed := now.Sub(stats.LastReset).Minutes()
        rpm := float64(stats.RequestCount) / elapsed
        
        if int64(rpm) >= d.threshold && !stats.IsHot {
            // Tenant became hot
            stats.IsHot = true
            stats.ShardCount = calculateShardCount(int64(rpm))
            log.Info("tenant became hot", "tenant_id", tenantID, "rpm", rpm, "shard_count", stats.ShardCount)
        } else if int64(rpm) < d.threshold/2 && stats.IsHot {
            // Tenant cooled down
            stats.IsHot = false
            stats.ShardCount = 1
            log.Info("tenant cooled down", "tenant_id", tenantID, "rpm", rpm)
        }
        
        // Reset counter
        stats.RequestCount = 0
        stats.LastReset = now
    }
}

func calculateShardCount(rpm int64) int {
    // Heuristic: 1 shard per 50k RPM
    shards := rpm / 50000
    if shards < 1 {
        return 1
    }
    if shards > 64 {
        return 64  // Max 64 shards
    }
    // Round up to power of 2
    return int(math.Pow(2, math.Ceil(math.Log2(float64(shards)))))
}
```

#### 4.3 跨分片聚合

```go
// Check checks rate limit across all shards for a tenant.
func (s *ShardedRateLimiter) Check(
    ctx context.Context,
    keys DimensionKeys,
    metric Metric,
    cost int64,
) (*LimitResult, error) {
    tenantID := keys.Tenant
    shardCount := s.getShardCount(tenantID)
    
    if shardCount <= 1 {
        // No sharding, use normal logic
        return s.checkSingleShard(ctx, keys, metric, cost)
    }
    
    // Aggregate across all shards
    var totalAllowed int64
    var totalLimit int64
    var totalRemaining int64
    
    for shard := 0; shard < shardCount; shard++ {
        shardKey := fmt.Sprintf("rl:%s:{%s}:shard:%d:%s", DimensionTenant, tenantID, shard, metric)
        
        result, err := s.checkShard(ctx, shardKey, metric, cost)
        if err != nil {
            return nil, err
        }
        
        totalAllowed += result.Limit - result.Remaining
        totalLimit += result.Limit
        totalRemaining += result.Remaining
    }
    
    // Check if total usage exceeds limit
    if totalRemaining <= 0 {
        return &LimitResult{
            Allowed:   false,
            Dimension: DimensionTenant,
            Metric:    metric,
            Limit:     totalLimit,
            Remaining: 0,
        }, nil
    }
    
    return &LimitResult{
        Allowed:   true,
        Dimension: DimensionTenant,
        Metric:    metric,
        Limit:     totalLimit,
        Remaining: totalRemaining,
    }, nil
}
```

## 二、Redis 集群模式兼容

### 2.1 核心问题

Redis Cluster 的关键限制：
1. **Lua 脚本只能操作同一个 hash slot 的 keys**
2. **多 key 操作用 hash tag 保证在同一个 slot**
3. **连接方式不同**（集群需要多个节点）

### 2.2 Hash Tag 设计

**原理**：Redis 使用 `{tag}` 内的字符串计算 hash slot，确保相关 key 在同一个节点。

**限流 Key 命名规范**：

```text
# 单维度 key（无 hash tag，自然分布）
rl:global:rpm
rl:tenant:{tenant_id}:rpm

# 多维度组合 key（使用 hash tag 保证在同一 slot）
rl:tenant:{tenant_id}:model:{provider}:{model}:rpm
                    ^^^^^^^^^
                    hash tag

rl:tenant:{tenant_id}:key:{key_hash}:tpm:input
                    ^^^^^^^^^
                    hash tag

# 分片 key（使用 hash tag 保证同一租户的分片在同一 slot）
rl:tenant:{tenant_id}:shard:0:rpm
                    ^^^^^^^^^
                    hash tag
```

**示例**：
```text
# 这些 key 会路由到同一个 slot（因为 hash tag 都是 "abc123"）
rl:tenant:{abc123}:rpm
rl:tenant:{abc123}:tpm:input
rl:tenant:{abc123}:tpm:output
rl:tenant:{abc123}:concurrency
rl:tenant:{abc123}:shard:0:rpm
rl:tenant:{abc123}:shard:1:rpm
```

### 2.4 Go 客户端实现（兼容单机和集群）

```go
// internal/ratelimit/redis_client.go

import (
    "github.com/redis/go-redis/v9"
)

// NewRedisClient creates a Redis client that works in both standalone and cluster mode.
func NewRedisClient(cfg *RedisConfig) (redis.UniversalClient, error) {
    // Determine mode
    clusterEnabled := false
    if cfg.Cluster != nil {
        switch cfg.Cluster.Enabled {
        case "true":
            clusterEnabled = true
        case "false":
            clusterEnabled = false
        case "auto":
            // Auto-detect: if multiple URLs provided, use cluster
            clusterEnabled = len(cfg.URLs) > 1
        }
    } else {
        // Auto-detect from URLs
        clusterEnabled = len(cfg.URLs) > 1
    }
    
    if clusterEnabled {
        // Cluster mode
        return redis.NewClusterClient(&redis.ClusterOptions{
            Addrs:        cfg.URLs,
            Password:     cfg.Password,
            MaxRedirects: cfg.Cluster.MaxRedirects,
            ReadOnly:     cfg.Cluster.ReadFromReplicas,
            
            PoolSize:     cfg.Pool.Size,
            MinIdleConns: cfg.Pool.MinIdle,
            MaxRetries:   cfg.Pool.MaxRetries,
            
            DialTimeout:  cfg.Timeout,
            ReadTimeout:  cfg.Timeout,
            WriteTimeout: cfg.Timeout,
        }), nil
    }
    
    // Standalone mode
    url := cfg.URL
    if url == "" && len(cfg.URLs) > 0 {
        url = cfg.URLs[0]
    }
    
    opts, err := redis.ParseURL(url)
    if err != nil {
        return nil, err
    }
    
    opts.PoolSize = cfg.Pool.Size
    opts.MinIdleConns = cfg.Pool.MinIdle
    opts.MaxRetries = cfg.Pool.MaxRetries
    opts.DialTimeout = cfg.Timeout
    opts.ReadTimeout = cfg.Timeout
    opts.WriteTimeout = cfg.Timeout
    
    return redis.NewClient(opts), nil
}
```

### 2.5 Lua 脚本适配（集群兼容）

**关键原则**：Lua 脚本中的所有 key 必须在同一个 hash slot。

**方案 A：单 key 操作（最简单，推荐）**

```lua
-- token_bucket.lua
-- KEYS[1]: 单个限流 key（如 rl:tenant:{abc123}:rpm）
-- ARGV[1]: cost
-- ARGV[2]: limit
-- ARGV[3]: refill_rate
-- ARGV[4]: now

local key = KEYS[1]
local cost = tonumber(ARGV[1])
local limit = tonumber(ARGV[2])
local refill_rate = tonumber(ARGV[3])
local now = tonumber(ARGV[4])

-- 所有操作都在同一个 key 上，天然兼容集群
local bucket = redis.call('HMGET', key, 'tokens', 'last_refill')
local tokens = tonumber(bucket[1]) or limit
local last_refill = tonumber(bucket[2]) or now

-- Refill
local elapsed = (now - last_refill) / 1e9
tokens = math.min(limit, tokens + elapsed * refill_rate)

-- Check and consume
if tokens >= cost then
    tokens = tokens - cost
    redis.call('HMSET', key, 'tokens', tokens, 'last_refill', now)
    redis.call('EXPIRE', key, 3600)
    return {1, tokens}  -- allowed, remaining
else
    redis.call('HMSET', key, 'tokens', tokens, 'last_refill', now)
    return {0, tokens}  -- denied, remaining
end
```

**方案 B：多维度联合检查（使用 hash tag）**

```lua
-- multi_dimension_check.lua
-- KEYS[1]: rl:tenant:{abc123}:rpm
-- KEYS[2]: rl:tenant:{abc123}:tpm:input
-- KEYS[3]: rl:tenant:{abc123}:tpm:output
-- 注意：所有 key 的 hash tag 都是 "abc123"，在同一 slot

local rpm_key = KEYS[1]
local tpm_input_key = KEYS[2]
local tpm_output_key = KEYS[3]

local rpm_cost = tonumber(ARGV[1])
local tpm_input_cost = tonumber(ARGV[2])
local tpm_output_cost = tonumber(ARGV[3])

-- Check all dimensions
local rpm_allowed = check_and_consume(rpm_key, rpm_cost)
if not rpm_allowed then
    return {0, "rpm"}
end

local tpm_input_allowed = check_and_consume(tpm_input_key, tpm_input_cost)
if not tpm_input_allowed then
    rollback(rpm_key, rpm_cost)
    return {0, "tpm:input"}
end

local tpm_output_allowed = check_and_consume(tpm_output_key, tpm_output_cost)
if not tpm_output_allowed then
    rollback(rpm_key, rpm_cost)
    rollback(tpm_input_key, tpm_input_cost)
    return {0, "tpm:output"}
end

return {1, "all"}
```

### 2.6 兼容性保证

| 问题 | 解决方案 |
|------|----------|
| Lua 脚本跨 slot | 使用 hash tag `{tenant_id}` 保证所有相关 key 在同一 slot |
| 单机 vs 集群配置 | 自动检测：多个 URL → 集群模式；单个 URL → 单机模式 |
| 热点租户 | Sharded 模式使用分片 key 分散到多个 slot |
| 读性能 | 集群模式可配置 `read_from_replicas: true` |
| 故障转移 | 使用 `redis.UniversalClient`，自动处理 failover |
| 连接池 | 集群和单机使用相同的连接池配置 |

## 三、流式场景的边界处理（核心设计）

### 3.1 核心原则：限流是入口闸门，不是输出过程中的刹车

**在途的流绝不截断，让它自然输出完。** 这是所有主流厂商（OpenAI、Anthropic、Azure）的通行做法。

### 3.2 预扣模式（Pre-deduction）

每个请求放行前，按它的 `max_tokens` 从 TPM 配额里预扣：

```
准入检查：TPM_remaining = 配额 - 已完成请求的实际消耗 - 所有在途请求的预扣值(max_tokens 之和)
```

### 3.3 预扣 + 后修正（避免保守）

```
请求进入：预扣 max_tokens
流式过程中：每收到 chunk，实际已输出 token 实时累加到 in-flight used
结束时：真实扣减 actual_tokens，预扣剩余部分退回
```

### 3.4 配置自洽性公式

```
并发数 × 平均输出token数 ≤ TPM(output) × 平均响应时长(分钟)
```

### 3.5 Overdraft 补偿机制

```
请求结束时：
  actual > 该请求预扣剩余配额 → 差额记为租户的 overage
  下个窗口或后续请求准入时，先从配额里扣掉 overage
```

## 四、核心接口设计（Facade Pattern）

```go
// internal/ratelimit/interface.go

// RateLimiter is the unified interface for all rate limiting modes.
type RateLimiter interface {
    // Check checks if a request is allowed.
    Check(ctx context.Context, keys DimensionKeys, metric Metric, cost int64) (*LimitResult, error)
    
    // Release releases concurrency quota (call after request completes).
    Release(ctx context.Context, keys DimensionKeys) error
    
    // Correct corrects pre-deducted quota with actual usage.
    Correct(ctx context.Context, keys DimensionKeys, metric Metric, preDeducted, actual int64) error
    
    // GetAvailable returns available quota for a dimension/metric.
    GetAvailable(ctx context.Context, keys DimensionKeys, metric Metric) (int64, error)
    
    // Reset clears rate limit data.
    Reset(ctx context.Context, keys DimensionKeys) error
    
    // Close cleans up resources.
    Close() error
}

// DimensionKeys holds the keys for all rate limiting dimensions.
type DimensionKeys struct {
    Global  string  // typically "global"
    Tenant  string  // e.g., "tenant:123"
    Model   string  // e.g., "model:openai:gpt-4"
    APIKey  string  // e.g., "key:abc123"
}

// Metric represents different rate limiting metrics.
type Metric string

const (
    MetricRPM         Metric = "rpm"
    MetricTPMInput    Metric = "tpm:input"
    MetricTPMOutput   Metric = "tpm:output"
    MetricConcurrency Metric = "concurrency"
)

// LimitResult represents the result of a rate limit check.
type LimitResult struct {
    Allowed    bool
    Dimension  Dimension
    Metric     Metric
    RetryAfter time.Duration
    Limit      int64
    Remaining  int64
}
```
